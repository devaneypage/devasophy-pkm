# Devasophy PKM Hub → Devanomy Integration Audit

## Reference strengths

The Devasophy PKM Hub reference presents a compact atelier dashboard with a clear three-part hierarchy: a branded navigation rail, a central knowledge-territory composition, and a narrow operational intelligence rail. Its strongest reusable concepts are the six knowledge regions, the explicit classification key, a concise accumulation chart, a relation-node preview, a recent-work panel, and an export-and-share panel. The reference is visually disciplined through cream paper, black ink, restrained primary colors, patterned geometric dividers, small uppercase labels, and serif editorial headings.

## Current Devanomy strengths

Devanomy already contains the mature functional substrate that the reference lacks: authenticated live metrics, a large Commonplace corpus, Clavis Aurea and Lexicon workflows, Research/Writing Studio, Goals and Ideas, Johnny Decimal taxonomy data, import/export, deduplication, protected AI insights, and persistent multi-record synthesis. Its existing visual system already shares the cream grid-paper background, navy shell, editorial serif typography, coral/gold/sky/violet accents, and patterned module cards.

## Integration direction

The overhaul should not reproduce the reference as a static dashboard. It should use the reference’s information hierarchy to reorganize Devanomy’s real capabilities. The dashboard should become a responsive atelier command center: compact live metrics and recent work at the top; a large editorial territory card; six live knowledge-region cards mapped to existing routes; a fixed content-type classification key; an accumulation chart derived from record timestamps; a relational-atlas preview grounded in existing cross-module links and synthesis concepts; a quick-synthesis action grid; and a compact export hub linked to the existing export workflow.

The global navigation should preserve every current route while simplifying visual hierarchy into primary knowledge workspaces, operational utilities, and the live Johnny Decimal outline. Existing content-type color tokens remain authoritative; region colors act as navigational accents rather than replacing the established taxonomy.

## Guardrails

No existing data model or route should be removed. All dashboard counts and activity surfaces must use existing application queries rather than hard-coded values. Empty, loading, and error states must remain useful. The dashboard must collapse coherently on mobile, preserve keyboard focus and reduced-motion behavior, and avoid placing critical actions behind hover-only affordances.

## Implementation visual review

The first integrated render preserves Devanomy’s existing identity while adopting the reference’s atelier hierarchy. Desktop verification confirms that the live metric strip, editorial territory card, geometric composition, recent-work list, Node Atlas, six-region grid, seven-month activity chart, classification key, quick-synthesis actions, and export hub form a coherent sequence. The grouped sidebar substantially improves wayfinding and removes the former duplicate Knowledge Base/Atlas destination.

Mobile verification confirms that all surfaces stack in the intended order without horizontal overflow: metrics, atelier card, geometric composition, recent work, Node Atlas, six regions, accumulation chart, classification key, synthesis actions, and export hub. Touch targets remain discrete and the visualization remains legible at narrow width. Final verification should focus on automated route/action assertions, loading/error behavior, and preserving reduced-motion treatment.
